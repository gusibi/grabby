# Grabby 订阅文本采集与归档

新建任务时，将前三个代码块分别复制到「任务背景」「首轮 Prompt」和「Rubrics 描述」。任务开始后，在各自的同一会话中依次发送第二至第四轮的代码块。同一轮统一发送同一份任务文本和样本。四轮结束后，只要仍有必做项未完成，就统一发送末尾的续跑提示。

## 任务背景

```text
我是 Grabby 的开发者和日常用户，用它订阅 RSS、技术公司博客、YouTube 频道和播客。现在，部分 RSS 只有摘要，关联文章可能暂时打不开。不同公司博客的列表结构各不相同，换站点后难以可靠地跟踪更新。YouTube 抓取有时只留下视频列表，旧条目缺少简介或字幕，也难以补齐。抓取后我还需要逐个打开源站，确认究竟拿到了哪些正文和字幕，以及缺失是因为源站没有文本、抓取失败，还是本轮跳过。

本任务要在现有 Grabby 仓库中完善订阅文本采集。手动或定时抓取后，我希望在内容库里读到文章正文、YouTube 原始简介及公开字幕，并在抓取日志中按条核对文章、视频和播客公开文字稿的采集结果。后续可以直接使用这些文本做检索和摘要。交付需要可运行的代码及可重复的一键验收。按现有仓库和样本范围估算，人工定位、实现与回归约需 2–4 个工作日，需要 Go、SQLite、RSS/HTML 解析和端到端测试经验。
```

## 首轮 Prompt

```text
你正在维护已有开发历史的 Grabby 仓库。请在附件中的代码基础上，完成「订阅文本采集与归档」第一阶段。请直接修改代码、运行测试和交付结果。

【场景与目标】

我是 Grabby 的开发者和日常用户。我用本地内容库跟踪 RSS、技术公司博客、YouTube 频道和播客。RSS 有时只有一段简介，原文链接也可能暂时打不开。不同公司的博客列表结构各异，切换站点时需要一种可复用的订阅方式。YouTube 只有视频列表时，我还得逐个打开视频找简介和字幕。

我希望从 Grabby 的正常订阅入口添加源后，手动或定时抓取都能发现新条目，将文章正文、YouTube 视频原始简介和公开字幕保存在现有内容库中。来源失败时，已取得的内容仍可读，之后能补齐缺失字段。每轮抓取结束后，我要能看到具体哪些文章、视频和播客单集拿到了什么文本，哪些失败、跳过或没有公开文本，以及原因。

【开始工作】

阅读仓库规则和 CONTEXT.md。确认当前版本中订阅配置、立即抓取、定时器、浏览器执行器、内容库和阅读接口的真实路径。尽可能运行基线测试，记录实际阻塞。后端已经有 RSS 深度抓取、网页抓取、YouTube 和播客适配器，请沿用适合的实现，检查历史条目跳过、配置可达性、条件请求和写库更新行为。公开字幕文本归档限于订阅内容库，保持独立平台采集 API 的既有存储策略。

样本由执行环境或以下字段提供：
- RSS 订阅 URL：https://hnrss.org/frontpage
- 播客订阅 URL：https://podcasts.files.bbci.co.uk/p02pc9wq.rss
- YouTube 频道 URL：https://www.youtube.com/@mattpocockuk/videos
- 同频道已知有公开字幕的视频 URL（可选）：https://www.youtube.com/watch?v=jVBlkOF8sHk
- 博客列表页实例：https://openai.com/news/ 和 https://www.anthropic.com/news

用本地固定样本完成自动验收。环境有公网访问能力时，经应用正常入口有限抽测以上真实样本。播客必须作为播客订阅单独验证，读取至少一个单集的简介、音频链接和逐条抓取日志，并核对该单集是否提供可访问的公开文字稿。若样本仅提供简介，记录实际结果，并用另一个本地固定样本验证公开文字稿成功入库。公网不可用时将相应在线用例标为未验证，用固定样本验证同类行为。仅采集公开内容，记录权限限制、登录墙、付费墙和外部访问异常。

【本地启动与数据隔离】

需要启动服务时，先确认当前目录是分配给你的独立仓库副本根目录。使用独立的 benchmark.db，日常 Grabby 的数据库、WAL 文件和 .env 不应复制进工作区。从副本根目录运行下面的命令，依次尝试 5141、5142、5143、5144。同机同时启动时，用临时目录占位，避免多个执行进程选到同一个端口。

bash <<'GRABBY_BENCHMARK'
cd go-server || exit 1
db_path="$(pwd -P)/benchmark.db"
for port in 5141 5142 5143 5144; do
  port_lock="/tmp/grabby-benchmark-$(id -u)-${port}.lock"
  mkdir "$port_lock" 2>/dev/null || continue
  if (</dev/tcp/127.0.0.1/"$port") 2>/dev/null; then
    rmdir "$port_lock"
    continue
  fi
  trap 'rmdir "$port_lock"' EXIT
  printf 'Grabby 验收地址：http://127.0.0.1:%s\n数据库：%s\n' "$port" "$db_path"
  HOST=127.0.0.1 PORT="$port" DB_PATH="$db_path" GOSUMDB=sum.golang.org go run .
  exit "$?"
done
printf '5141–5144 均已占用或被其他执行任务预留。\n' >&2
exit 1
GRABBY_BENCHMARK

这是无界面 Go 服务。使用启动命令打印的地址，核对实际监听端口和进程打开的数据库绝对路径，再发起验证请求。不要使用日常 Grabby 的 5040 端口、桌面 App 或 make app。四个端口均不可用时，记录冲突并继续可在临时数据库中运行的测试。

【功能要求】

A. RSS/Atom 文章正文
- 让正常订阅入口可以启用、保存和重读抓取全文设置。兼容已有 full_content 和 fetch_full_via_scrape 配置。选项关闭时维持 Feed 采集行为。
- Feed 内已有正文就保留。仅有简介或链接时，启用后访问公开原文并提取可读正文，保留原摘要和来源链接。接受相对链接和正常重定向。
- 原文暂时获取失败或提取失败时保留已取得的简介，提供可诊断的状态或日志。开启全文后可补齐已有摘要条目。原文恢复后，即使 Feed 返回 304，也要有途径补齐已知条目。补齐时保留条目 ID、已读和收藏状态。

B. 非标准博客列表
- 用户可从正常订阅入口用公开博客列表页 URL 建立订阅，并通过现有定时器或立即抓取发现文章。使用同一套发现与提取流程处理至少两种列表结构。允许用每源配置指定列表区域或文章链接规则，切换站点可通过配置完成，博客示例无须专用域名分支。
- 解析相对链接并去重，过滤导航、标签及其他非文章入口。打开文章页，保存标题、正文、来源链接以及页面可提供的发布时间。限制每轮工作量。单篇失败有据可查，同轮其他文章可正常入库。
- 列表更新后可新增文章，重复轮询不会产生副本。兼容既有单篇网页订阅和旧配置。

C. YouTube 频道简介和字幕
- 从正常订阅入口配置博主频道，至少支持频道 ID 和 @handle，轮询发现视频。保存视频链接、标题、原始简介和可访问的字幕。简介和字幕能在内容库辨认，记录字幕来源和可获得的语言。
- 接受 YouTube 已发布的人工字幕及自动字幕。明确无字幕、临时获取失败或状态未知时仍保留视频和已取得的简介，状态能区分。没有字幕时保持字幕为空。
- 旧列表条目和临时失败的条目可补齐。按视频身份处理不同 URL 写法，重复或重叠运行不会新增副本。后续不完整结果不得覆盖已有简介或字幕。已有条目更新时保留用户状态。

D. Podcast 播客公开文字稿
- 沿用现有播客订阅路径，保存单集链接、节目简介和音频链接。源提供受支持且可访问的公开文字稿时，将文字稿及来源一并保存。从内容详情或阅读器能分别读到节目简介和文字稿。
- 无公开文字稿或文字稿获取失败时，保留节目简介和音频链接，在逐条抓取日志中区分实际结果。验证原有播放入口仍可使用。
- 第一阶段复用公开文字稿采集能力。无公开文字稿的播客转写、无字幕视频转写、下载或归档音视频文件留到第二阶段。

E. 每次抓取的条目明细
- 沿用订阅的「抓取日志」入口，持久化每轮手动或定时抓取记录。能按订阅源和本轮记录查看触发方式、开始和结束时间、整体结果及逐条明细。桌面端可从抓取日志查看，应用 API 提供对应的可查询结果，供自动验收。保留已有历史日志的读取能力。
- 对本轮发现并处理或有意跳过的条目，记录标题（获取不到时用链接）、来源链接、结果和原因。对于已入库条目，记录内容库 ID，供定位和读回。对每种文本分别记录获取结果和来源，例如 Feed 自带正文、原文页面、博客文章页、YouTube 字幕轨道、播客公开文字稿链接。按实际结果区分已入库、保留已有文本、未尝试或跳过、确认无公开文本、失败或未能确认。失败明细应指出发生在访问、提取还是入库，以及可获得的具体原因（如 HTTP 404、超时或解析失败）。
- RSS 要看得出本轮是否尝试打开原文、是否成功取得并保存正文，或者仅保留了 Feed 简介。博客要看得出哪篇文章已保存正文。YouTube 要分别显示每个视频的简介和字幕结果。播客要分别显示每集节目简介和公开文字稿的结果，沿用现有公开文字稿采集行为。日志保存结果、原因和定位信息，正文与字幕仍从内容库读取。日志中的链接和错误信息须去除凭据。
- 一轮内有成功也有失败时，两种结果均可见。列表页访问失败、Feed 304、无新条目和异步任务尚在处理应有可区分的运行状态。异步任务完成后记录最终结果，只有内容实际写入后才标记入库成功。补抓成功另有本轮记录，之前的失败仍可查。

所有订阅类型均需保留创建、编辑和触发能力，兼容已有配置及调用方。新增链路无需下载音视频或调用转写服务。

【自动验收】

提供一个可从干净检出运行的仓库内命令。依赖安装后，核心验收须用本地 HTTP、固定 Feed/HTML/字幕样本、临时 SQLite，以及必要时可控的浏览器执行器替身运行，无需公网、人工点击、登录或模型 API。固定样本应走生产解析与持久化。至少一组测试从应用订阅创建或更新入口开始，触发真实抓取，入库后从内容详情接口读回。另验证现有定时器能触发同一抓取链路，使用可控触发或有时限的测试。

应有自动断言覆盖：
1. RSS 已有正文被保留，摘要或链接能补入正文，关闭全文时不请求原文。一轮失败、一轮恢复且 Feed 返回 304 后，旧条目补齐正文，原摘要、ID、已读和收藏保留。
2. 两种博客结构得到正确文章集合和正文。导航、标签、重复候选排除。列表更新后只新增新文章，单篇失败不影响其余条目。
3. YouTube 频道发现视频，保存原始简介和有字幕视频的文本。区分明确无字幕与临时失败。已有列表条目恢复后补齐，重复抓取与较差结果不会产生副本或丢失已有文本。
4. 播客固定样本覆盖公开文字稿可用、只有节目简介、文字稿链接失败三种单集。从内容详情核对文字稿、简介和音频链接，从日志核对文字稿状态。断言缺稿时仍保留简介和播放链接，采集未下载媒体。另覆盖应用配置写入和重读、立即和定时触发、重复或重叠运行，以及原 RSS 和单篇网页行为。
5. 从应用日志 API 读回每轮逐条明细，并用内容 ID 核对实际保存的文本。覆盖 RSS 自带正文、原文打开并入库、原文失败后仅保留简介及后续补抓，博客同轮成功和失败，YouTube 简介成功但字幕缺失或失败，以及播客有公开文字稿和仅有节目简介。断言无更新或跳过可辨认，异步明细能更新为最终结果，重新打开数据库后仍能查到记录，且上轮失败和本轮成功能分别查到。模拟入库失败时，日志不得报入库成功。

运行一键验收和仓库已有回归测试。Go 回归命令通常是 cd go-server && go test ./...。涉及桌面入口或浏览器扩展时，按仓库提供的条件执行对应验证。已提供真实样本、环境可访问时，经实际应用链路有限抽测，记录来源、时间、本轮抓取记录 ID、条目 ID、结果和少量正文或字幕证据。将固定样本和在线测试结果分别记录。

【交付和完成条件】

交付可运行的代码、自动验收入口与样本、最小使用说明和验收记录。使用说明应能让用户配置 RSS、博客、YouTube 和播客订阅、补抓已有条目、从抓取日志查看逐条结果并在内容库读到文本。验收记录按 A 至 E 列出涉及文件、实际执行命令、断言或证据位置，以及通过、失败或未验证的状态。附一份从应用查回的抓取明细示例，包含成功、失败和跳过或无公开文本的条目。环境或样本阻塞时注明原因。项目既有失败应注明基线与改动后的情况。

本轮请尽可能完成全部范围。若本轮结束时仍有未完成项，保留已完成的仓库改动，列出每个缺口的具体位置、对应验收和实际阻塞，便于在同一会话继续。
```

## Rubrics 描述

```text
按以下维度检查实际运行结果和可定位的交付证据。

1. RSS/Atom 全文。开启时能从公开原文补齐摘要条目，关闭时保留 Feed 行为。原文暂时失败后可以补齐，覆盖已有条目和 Feed 304。已读、收藏、ID 和已有正文保留。
2. 博客增量采集。用同一套流程处理至少两种列表结构，取得正确的文章集合和正文，排除导航及重复链接。定时更新只新增应新增的文章，单篇失败可定位且同轮其他条目可入库。
3. YouTube 简介和字幕。通过频道发现视频，分别保存原始简介和可访问的字幕，并记录字幕来源和可获得的语言。区分无公开字幕与获取失败，验证旧条目补齐、不同 URL 去重和已有内容保护。
4. 逐条抓取记录。手动和定时抓取都能查到每轮及每条明细，覆盖 RSS 原文、博客正文、YouTube 简介与字幕、播客简介与公开文字稿。成功、失败、跳过和无公开文本能区分，失败有具体阶段和原因，补抓成功后之前的失败仍可查。日志标为入库成功时，内容 ID 必须能读回对应文本。
5. Podcast 播客公开文字稿。公开文字稿实际入库，能与简介分开读回并核对来源。无文字稿或获取失败时保留简介和播放链接，日志准确区分原因。BBC 示例单独抽测，环境无法访问时如实记录，并以固定样本验证。
6. 自动验收与兼容性。一键命令能在隔离环境中重跑，从真实订阅入口验证到内容详情和日志 API，覆盖异步结果、失败恢复和旧条目。原有配置通过回归，交付含使用说明、运行命令和证据。

优秀：六个维度均有可复现的运行证据。固定样本覆盖成功、部分失败、跳过、恢复及重复抓取，逐条日志与实际入库文本一致。交付清楚记录线下与在线验证结果，有环境限制时能说明具体影响。

合格：RSS、博客、YouTube 和播客公开文字稿主链路可用，关键成功与失败结果能逐条核对，提供可运行的一键验收和相关回归记录。轻微缺项可定位，且不妨碍正常使用。真实样本未提供或公网不可达时，如实标记在线未验证，并用固定样本证明对应行为。

不合格：任一主要来源的主链路无法使用，或出现把摘要当正文、把简介当字幕、入库失败却记成功、丢失已有文本或用户状态等问题。只有列表或总数、没有可查询的逐条日志，缺少可运行的一键验收，或将未执行的验证标为通过，均视为核心交付缺失。
```
